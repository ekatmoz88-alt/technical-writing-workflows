03 / Sample contract

A small API to validate the workflow.

The repository includes a deliberately minimal fictional Tasks API. It provides realistic documentation material without depending on a live backend.

Documented operations

GET
/tasks

Returns an array of task objects with id, title, and completed fields.

POST
/tasks

Creates a task using a non-empty title. Successful creation returns HTTP 201.

The Markdown overview links to the OpenAPI specification as the source of truth for endpoints, request bodies, response codes, and schemas.

Example request

# Create a sample task
curl -X POST \
  https://api.example.com/v1/tasks \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Review API documentation"
  }'

Example response · 201

{
  "id": "task_123",
  "title": "Review API documentation",
  "completed": false
}
04 / Implementation

Readable, version-controlled configuration.

The CI definition is maintained alongside the documentation in .github/workflows/lint.yml.

Workflow configuration

on:
  push:
    branches: [main, master]
  pull_request:
    branches: [main, master]

steps:
  - Checkout repository
  - Set up Node.js 22
  - Install Spectral CLI
  - Validate OpenAPI spec
  - Lint Markdown
  - Check Markdown links

Run checks locally

spectral lint openapi/openapi.yaml

markdownlint docs/*.md

lychee --verbose --no-progress './**/*.md'

Install the corresponding CLI tools before running these commands. The GitHub Actions workflow installs or invokes the tools as configured in the YAML file.
